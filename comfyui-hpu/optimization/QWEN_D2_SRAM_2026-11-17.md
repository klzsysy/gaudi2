## 设计细节

每个tile记录Q/K/V、score、概率、FP32 max/sum与输出累加的字节，计入双缓冲和运行时保留区。query和KV的余数独立处理，padding不得参与softmax。在线归一化使用稳定max/sum合并，先测BF16矩阵及FP32统计，再独立评价低精度概率。编译器dump中的分配和原生HBM计数共同确认驻留。

显式分块会改变矩阵形状和舍入，分别对CPU FP64抽样及D1比较。初筛同时记录首层、中间层和末层，后续覆盖全部76组真实输入、每个head和完整采样轨迹。新的数值边界需由误差来源和完整质量证据确定。

候选保持原节点和dispatcher入口，覆盖mask、自定义scale/GQA、dtype、CPU、禁用编译、训练与显式关闭。任何可重用执行计划只保存编译元数据。提示词/seed、Q/K/V和可变输出状态每次调用更新，A→B→A、相同shape新内容和跨KV边界必须进入回归。

### 编译图和初筛

Qwen自己的post graph确认QK scores为DRAM，概率为SRAM。负条件主体每head先按KV2176/2048分QK，输出覆盖8160 queries；softmax/AV按query1024/992分块。两端分块不一致。32 heads完整attention的score写出逻辑量约4.479GB，单次写读约8.957GB。

独立固定输入attention为9.296ms。把query折叠为256/512/1024行增加到10.906/10.850/11.047ms，scores继续在DRAM。显式query2048循环为8.483ms、512循环9.422ms，作为后续组合候选保留。

七组compiler配置覆盖flash slicing、layered pipeline、attention seeds、组合、32/40MiB SRAM预算和fold256。Set/Get读回成功，计时约9.293–9.312ms，score分配一致。显式QK/softmax/AV及user_bundle_id同样保留DRAM score。初筛总计26个执行案例，记录于`initial`、`compiler`和`bundles`。

D1原生时间线重新按类别计算，658.399ms设备跨度中，TPC独占约191.372ms、softmax独占91.192ms、SDPA MME独占95.504ms、SDPA MME与softmax重叠74.655ms。具名kernel覆盖95.43%，事件配对无遗漏。完整block已经捕获用于定位剩余norm、量化和数据流费用。

### 公共Synapse RMW驻留路径

本机SDK的`DEVICE_ATTRIBUTE_MAX_RMW_SIZE`为16MiB。独立CPU建图证明，可以用同一RMW section将scores和probabilities同时放入SRAM。原位同offset方案由编译器加入SRAM→SRAM保护拷贝，post graph中这条链没有中间DRAM tensor。不同RMW section分别承载同一个softmax的输入/输出在节点创建时被拒绝，共享section可编译。

标准Synapse流执行的shared、alias、fast合成检查及真实Q8160/K8576均通过。q448、两个RMW slot的真实32-head核心19.776ms，慢于D1。单head同配置0.617ms，32 heads在一个大图内编译花费261.99秒，这种大图构建方式退出产品候选。单head模板编译约0.047秒，后续基于它继续考察tile、统计输出和提交粒度。raw fast inverse统计需要核对缩放，与PyTorch SDPA公开返回的语义分别验证。

### RMW内核和调度复验

单head的query tile扫描覆盖128/256/384/512/768/896/960与1/2/3个RMW slot。厂商fast softmax在K8576、q960下为0.506ms，完整有效K8607、q896为0.696ms。原始fast inverse约为FP64归一化倒数的1/128，需要先匹配其内部统计尺度再用于tail合并。

新增隔离TPC原型直接接收MME的FP16 scores，精确逐行max后计算BF16未归一化概率和FP32行和，AV输出FP32后归一化。通过`inputReusabilityBinding`声明输入复用，post graph确认scores与probabilities均驻留SRAM，原位保护copy消失。真实输入FP64 RRMSE为0.190%–0.225%，31/127/128/129/256余数边界及重复运行通过。

这个稳定softmax原型仍慢。多项式版本单head约1.64–1.78ms，builtin BF16 exp约1.40–1.47ms。显式QK提前依赖、双slot和四倍展开没有形成净收益。进一步复现默认exp LUT的有限输入序列、延后max的FP32转换，得到1.404ms，数值与builtin exp一致。该路径使用框架默认特殊函数表，未替换全局LUT。编译后的24个TPC均参与，汇编中的长依赖链和串行归约仍需重写。

直接SCAL核心的6.632ms说明片上路径有空间，但完整API的native约13.7–14.0秒、block/native约11.6秒，均慢于block/query组合的约10.9秒。现有每次请求的数据准备、执行计划及同步边界仍有成本。上述原型保留在调查目录，用于下一轮跨框架数据流研究。

### 二、三条片上SRAM流水探索路线受阻的技术根因

1. **PyTorch/Bridge编译器配置引导（26组实验全部落DRAM）**：
   - `sdpa_recomp_fwd`在`Q=8160, KV=8607`下，QK MME按`KV=2176/2048`切分（覆盖全部8160行query），而softmax/AV按`query=1024/992`切分。生产端（切K）与消费端（切Q）分块维度正交，迫使完整score矩阵物化到DRAM。
   - D1为拆分非128对齐KV传入`requires_backward=True`以获取`maximum/inverse`，在bridge中关闭了inference标记，阻断推理期Flash Slicing策略。
2. **直接SCAL/QMAN原生硬件流水（核心6.63ms，但端到端11.6–14.0秒反慢于D1）**：
   - 借用的`exp_f16_logq`采用固定偏移（无row-max），每次attention调用必须在HPU执行`prepare()`计算范数上界`gates`，随后执行**`gates.cpu().tolist()`＋2次`torch.hpu.synchronize()`全设备硬同步**，在CPU判定是否溢出回退。16步×31层＝496次调用产生近千次全卡Pipeline Drain，击碎PyTorch HPU Eager异步流水。
   - 静态QMAN描述符写死`plan.qh/kth/vh`物理地址，每次调用需`~0.93ms`显式staging copy与清零（累计约0.46秒额外拷贝与HBM读写），且`@torch.compiler.disable`打断编译图。
3. **公共Synapse C API＋RMW SRAM Section路径（已证100%片上驻留且单Head极快，卡在建图方式）**：
   - 利用Gaudi2的16MiB RMW Section，单head在`tile=960, fast=true`下仅`0.506ms`，在`tile=896, fast=false`（精确`softmax_fwd_bf16`，直接支持非对齐`KV=8607`）下仅`0.869ms`（FP64 RRMSE `0.644%`），post-graph确认scores与probabilities 100%驻留SRAM，且直接在默认`_compute_stream()`异步`synLaunch`。
   - **受阻点**：`qwen_d2_rmw_runtime.cpp`用双层循环将`32 heads × 19 tiles`平铺展开为1824个2D节点及上千个独立`persistent` section切片绑定，导致32-head单图编译耗时261.99秒、执行退化至19.78ms；而单head每tile独立persistent绑定在`reduced=1`时触发`synStatus 30`。
4. **自写TPC-C稳定Softmax核（`qwen_d2_softmax/core.c`）**：
   - `inputReusabilityBinding`成功消除RMW原位保护拷贝且FP64 RRMSE低至`0.19%–0.225%`，但外层按单行串行循环、`max64_no_lut/sum64_no_lut`跨通道归约气泡、`F16→F32→BF16`冗余转换及`exp_finite` 8条RAW依赖指令单链串行，加之PV输出FP32后外接`div_fwd_f32 + cast`，导致单head耗时`1.400ms`。

### 三、更好的实现方案设计（优先推进方案A）

#### 方案A（首选，真正兑现D2片上SRAM驻留）：公共Synapse RMW **“4-Persistent基地址绑定 / 3D Head-Group模板复用 / 精确或尾段合并流水”**
在不依赖私有SCAL流、无`synchronize()`同步回读、无staging copy的前提下，直接在PyTorch默认`_compute_stream()`上重构`qwen_d2_rmw_runtime.cpp`：
1. **消除Persistent Binding爆炸与`synStatus 30`**：每个Synapse recipe只绑定少数组基地址（或利用同一persistent section内的固定tensor offset直接传入连续的BHND `Q, K, V, O`设备指针），或者对单head/多head分组模板通过微秒级异步`synLaunch`循环提交32个head（每个head仅更新`Q, K, V, O`的head偏移地址），使recipe编译时间保持在**`0.03–0.10秒`**量级。
2. **3D Batch-GEMM / Head-Group分块与双Slot流水**：测试单head及`H_group = 2/4`的3D `batch_gemm` + 3D `softmax_fwd`组合（在16MiB RMW上限内选择最优`(H_group, q_tile, slots)`），对比单head模板32次异步`synLaunch`与多head分组模板的设备端真实耗时与HBM流量。
3. **同时支持“无损精确模式（Exact BF16 Softmax）”与“极速模式（Fast HF8 Softmax＋尾段合并）”**：
   - **精确模式（`softmax_fwd_bf16`）**：直接处理完整非对齐`KV=8607/9445`（无需128对齐拆分与统计量合并），scores与probabilities全驻留RMW SRAM，验证其在消除每层`8.96GB` DRAM score流量的同时，能否同时改善速度和图像质量（消除fast softmax误差）。
   - **极速模式（`softmax_fwd_hf8`）**：对齐主体（如`8576`或`9344`）在RMW SRAM内以`0.506ms/head`运行，结合尾段（或padding mask）完成完整输出，接入CustomOp/编译边界验证端到端DiT耗时、HBM流量与显存峰值。

#### 方案B（PyTorch层零显存暴涨、零画质劣化的子图融合）：**拆分整Block大图为“Pre-Attention共享FP8量化子图”＋“2048-Query无损切分Attention”＋“Post-Attention/FFN子图”**
1. 放弃跨Attention与FFN的整block大图编译（消除`+11.31GiB`显存峰值与蓝衣画质偏移）。
2. 将`img_norm1`后的`to_q/to_k/to_v`改为共享单次激活FP8量化（消除2/3重复`amax + cast_to_fp8_v2`），并与`_hpu_rms_rope`组成轻量前段子图；将`to_out + _gated_residual1 + _modulated_norm2 + FFN + _gated_residual2`组成后段子图。
3. 保留已证逐像素一致（MAE=0）的Attention内部`2048-query`切分，并用零拷贝视图/预分配输出替代`contiguous() + cat`。

#### 方案C（自写TPC Softmax向量流水重写）：**4行交错向量链（4-Row Interleaving）＋原生BF16输入＋SRAM内原地归一化**
1. 外层循环4行并行展开，交错发射4组`v_bf16_ld_tnsr_b`、`v_bf16_max_b`与`exp_finite`指令链，隐藏VPU延迟与归约气泡。
2. MME直接输出BF16 scores，消除FP16↔FP32↔BF16转换，并在TPC核内或PV后融合归一化。

## 2026-11-18 方案A（公共Synapse RMW片上SRAM流水）实现、硬件验证与部署

按用户要求推进方案A，在不依赖私有SCAL流、无`torch.hpu.synchronize()`同步回读、无整block大图显存膨胀的前提下，通过公共Synapse C API构建RMW片上SRAM流水并接入产品`comfy/ldm/modules/hpu_attention.py`与`comfy/ldm/modules/attention.py`。

### 一、关键技术突破与实现细节

1. **4-Persistent基地址绑定＋Logical `split/concat`消除编译爆炸与`synStatus 30`**：
   - 将`Q, K, V, O`声明为每个Head-Group仅4个persistent张量，图内使用Synapse逻辑`split`与`concat`切分`(group_heads × tiles_per_head)`个2D `gemm`与`softmax_fwd_hf8`节点，编译后自动折叠为零拷贝基地址偏移。
   - 在16MiB RMW Section内采用双slot环形缓冲（`slots=2`），通过显式依赖边（`qk[i-1] -> qk[i]`、`qk[i] -> pv[i-1]`、`pv[i-1] -> pv[i]`、`pv[i-2] -> qk[i]`）强制MME与TPC跨tile交错执行，编译后recipe `workspace = 256` bytes，证实`scores`与`probabilities` 100%驻留片上SRAM。
   - `group_heads=4, slots=2, tile=448/480`模板单次编译仅`0.30–0.44`秒，32个head仅需8次微秒级异步`synLaunch`（直接在PyTorch默认`_compute_stream()`提交，调用前执行`join_pending_pipeline_threads()`确保Eager/编译输入地址就绪）。
2. **128对齐RMW主体＋尾段合并（`split-sdpa-tail`）与D1 100%逐位一致（`rrmse = 0.000000`）**：
   - 对比实验表明：`softmax_fwd_bf16`精确模式单次32-head耗时`18.23ms`（慢于D1的`9.41ms`）；`softmax_fwd_hf8`在`FUSED_ADD`掩码模式下忽略`-inf`掩码，导致非128对齐尾段（如`K=4225`填充至`4352`的127列零键）产生`exp(0)=1`权重偏差（误差2.92%）。
   - 采用`split-sdpa-tail`方案：128对齐主体`split = (K // 128) * 128`（如`8576`或`9344`）在RMW SRAM内以`SOFTMAX_HF8_1C | SQUEEZED_RETAINED`执行并输出`(first, max1, inv1)`（统计量按64行对齐输出以消除TPC RMW写回惩罚），短尾段`K - split`（`31`或`101`列）由编译子图内的`sdpa_recomp_fwd`计算`(last, max2, inv2)`，再由编译子图`_merge_tail`合并。
   - 审计D1 post-graph发现`sdpa_recomp_fwd`在`qk`矩阵乘前对`q`（而非`k`）乘以BF16标量`scale = 128 ** -0.5`（`0.08837890625`）。在`_prep_aligned`与`_prep_split_and_tail`编译子图中使用`scale = torch.full((), q.shape[-1] ** -0.5, dtype=q.dtype, device=q.device)`缩放`q`，使方案A与D1的数值舍入边界**100%逐位一致（Bitwise Identical）**。
3. **消除`hpu::batch_as_strided`别名告警与动态图重编译**：
   - 在`_prep_split_and_tail`中符号化计算`split = (k.shape[-2] // 128) * 128`，使不同文本长度共享同一动态编译图（`recompile_limits == 0`）。
   - 在`attention_pytorch`中通过`@torch._dynamo.disable`入口`_hpu_fast_attention_entry`在`_reshape_qkv_to_heads`与`transpose(1, 2)`之前完成分发，避免TorchDynamo在图中断前生成仅含3个输入视图的FX子图，从而彻底消除`UserWarning: hpu::batch_as_strided`（`alias_warnings == 0`）。
