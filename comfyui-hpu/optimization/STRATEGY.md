# 优化方向与实验重启条件

2026-11-15用户随后授权部署候选体验。普通服务现运行产品`92d15ff7`，使用生成调用级状态代理接入GDN直接更新、SDPA和整步编译。候选数值、普通API图片及卸载重载一致性验证通过，用户可在原8189工作流中体验。[上线记录](QWEN21_EXECUTION_DEPLOYMENT.md)

2026-11-15完成用户要求的逐项验证。GDN直接状态更新与整步编译组合贡献主要收益，短固定文本约降低35%，加入SDPA后约36%。原2MP固定1784-token完整工作流PE降低39.60%、整图降低27.17%，HBM有效带宽利用率升至47.72%。自然出图4组已交付检查，静态容量首次编译成本、数值变化及候选调用范围均保留。普通产品继续为已验收`dfca7cd6`。[完整结果与边界](QWEN21_EXECUTION_VALIDATION.md)

2026-11-15用户要求先校准HBM，再推进整步执行复用和GDN融合，优先充分利用无MTP的BF16路径，MTP集成暂缓。校准得到单token约18.43 GB读写、峰值带宽约33%。整步重放和GDN候选已有局部/固定文本收益，仍需检查数值差异、完整自然生成质量及正常生成生命周期。[校准依据](QWEN21_BF16_SINGLE_TOKEN.md)

用户随后人工接受产品`dfca7cd6`。新增根因实测表明，大块MLP/输出头权重有效带宽约2.00/2.20TB/s，主线程CPU约17.3ms/token，原生trace为306 recipes/token。核心20.85ms，跳过GDN核心为15.80ms，同时跳过GDN核心与完整attention为9.57ms。这些消融用于确定优先级，后续集中处理单token GDN与完整attention的执行链，再组合整步执行。候选的数值差异需推进质量验证，逐元素一致不得自行设为统一硬门槛。普通服务保持已接受版本。[根因与方法修正](QWEN21_DECODE_ROOT_CAUSE.md)

2026-11-13阶段的产品为`34e2649e`。质量保值优先，当时可确认收益来自FP8长序列query批次和文本短步RoPE，BF16整block共享候选在恢复舍入边界后无稳定净收益。历史算法量化的误差与最新保值实现分别见各主题。

2026-11-14用户将原生INT8 MME设为继续条件，HAL与直接Synapse能力验证阴性，通用INT8开发已停止并放弃。[验证结果](INT8_NATIVE_MME.md)与[历史计划](INT8_DEVELOPMENT_PLAN.md)已归档。以下保留此前其它优化方向与候选取舍。

## 此前投入方向

| 方向 | 已有依据 | 下一个有意义的实验 | 接入依据 |
|---|---|---|---|
| Attention的bridge/lowering与片上协作 | QK分数非persistent但落DRAM，概率tile已在SRAM；长序列分批省2.54% | 同精度最小子图对齐FX、Synapse图与trace，改变QK/softmax共同tile或bundle | 实际驻留变化、90组真实输入/长序列、完整图净收益 |
| 文本控制与提交 | 16轮低扰动窗口间隙39.7%，RoPE后FP8/BF16文本分别省4.63%/2.98% | 关联主机控制、recipe入队和设备空档，合并确定性计算或减少必要回读 | 固定logits、commit/rollback、固定树自然采样及完整API |
| TPC复合计算 | SiTU独占约1.01s，量化约0.20s，手写初版均未超过当前编译 | 按生成图优化norm/调制/量化或SiTU衔接，保留原归约和舍入 | 完整区域成本及敏感层误差，计入布局/转换/显存 |
| BF16专项 | 大Linear374–404TF/s，常规布局/双层/开关收益收窄 | 新attention实现或明确改变图结构的共享优化 | 以同轮BF16参考证明额外收益 |
| HBM计数与运行时稳定性 | 原始stall/ACT已取得，BMON字节未校准，部分调查进程崩溃未定位 | 已知读写控制校准，故障最小复现与配套SDK比较 | 可复算的计数语义或可复现故障消除 |

FP8主线已有较大的历史收益，但FP8 Linear活动阶段约806TF/s，继续提高原语峰值对应完整流程空间较小。保留BF16 QK和敏感FP32操作，优先改变数据流与提交结构。文本FP8的主要已验证收益为显存，进一步执行优化对两种文本格式均有价值。

## 失败结论何时值得重测

| 历史路径 | 失败或收益未确认的原因 | 重启条件 |
|---|---|---|
| 全FP8 QK | 深层误差18.5%–48.1% | 新校准/精度方案并通过多层/timestep参考 |
| fast softmax | 局部快但FP64误差0.314%→0.721% | 新保值实现或精度证据 |
| CFG合批、补齐、query分块 | 适配/复制成本、退出既有快路径或额外舍入 | 新shape、dispatcher支持或真实存储/调度变化，长序列分批已提供成功案例 |
| SRAM预算32MiB | 90组相同但整段中位数/均值方向相反，scores仍DRAM | 能改变图规划并复现净收益 |
| GDN TPC四列核心 | 局部快，完整FP8/BF16 logits漂移与图像缺陷 | 找到保留累积舍入的方法，固定程序和自然图一起过关 |
| GDN扩区 | 旧递推组合更慢，后续并行递推后成功 | 算法或图结构改变后重新测边界 |
| 小M FP8额外编译 | 额外数值差异和异步重载失败 | 新lowering/运行时版本或具体输入问题修复 |
| lazy/Graph | 逐请求capture成本、误差及ABI失败 | 长生命周期capture设计或配套SDK变化 |
| 通用INT8/W4A8加速 | 原生INT8 MME验证阴性，用户要求停止 | 已停止、已放弃，见[验证结果](INT8_NATIVE_MME.md) |

## 需要单列的优化目标

冷启动、跨shape、吞吐和单请求warm各有不同费用。既有cold约65–100秒包含读取、转移、准备和编译，尚未完整拆分。recipe缓存或长生命周期buffer应计入失效和padding成本。多请求batch可能摊薄文本提交，也会争用HBM/TPC，需记录排队与单请求延迟。

跨请求前缀缓存需KV/GDN/conv状态及模型/LoRA/位置失效契约，当前prefill首步约0.254秒，首先量化可覆盖预算。减少步数、缩短扩写、跨步特征复用或蒸馏改变工作量，应建立各自速度/质量曲线。
